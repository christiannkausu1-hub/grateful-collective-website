THE GRATEFUL COLLECTIVE — FUNCTIONAL REPAIR NOTES

Repairs applied to the existing website package:
- Removed the separate legacy pupil, payroll and shop card-collapsing handlers and replaced them with one idempotent card setup. It does not clone headings, does not run a whole-page MutationObserver, and ignores interactive controls so action buttons do not toggle cards. Trade Payables remains excluded.
- Kept the class-list action independent from card toggling.
- Kept Dashboard LEFT TO PAY and Workers & Payroll total on one selected-month unpaid-net-pay calculation.
- Removed NAPSA from ordinary Workers & Payroll entry, calculation, edit modal, payslip and CSV export. Teacher NAPSA return registration remains a separate feature. Existing historical NAPSA database values are not deleted or rewritten.
- Reworked rent-payment save order to create the rental payment, create the linked income transaction, and explicitly check rollback and link-update failures.
- Reworked rent-payment deletion to remove the linked transaction first, then the payment; if payment deletion fails, the transaction is restored and the rental row is relinked to its new transaction ID.
- Preserved all 19 original package files, including assets, manifest, service worker and SQL migration scripts. Every file is at the ZIP root.

Static validation performed:
- ZIP integrity/CRC check passed.
- Inline JavaScript syntax checked with Node.js.
- Duplicate HTML IDs: none found.
- Card handler audit: one card setup system remains; legacy pupil/payroll/shop card setup scripts removed.
- Ordinary payroll NAPSA input/edit field removed; separate teacher return feature retained.

Limitations:
- No live browser interaction test was run.
- No live Supabase/RLS test was run and no SQL migration was executed.
- Multi-table rental operations now perform checked compensating actions, but true atomicity requires a Supabase database RPC/transaction. If the app loses connectivity during a compensating action, manual reconciliation may still be required; the interface reports that failure.
- Existing database records are not modified by building this package.
